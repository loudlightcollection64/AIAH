## Checked and found correct (don't re-check)

- **PHP 7.4:** no `match`, `?->`, named arguments, union/mixed/static return types, `readonly`, enums, `never`, `fn`, first-class callables, attributes, `str_contains`-family, `array_is_list` or `0o` anywhere in the plugin (grep over all `.php`). `intdiv`, `??`, `\Throwable`, `const` arrays and `DateTimeImmutable` are all fine on 7.4. `fputcsv` passes the escape character explicitly (`export.php:140`).
- **Fluent Forms hooks:** `fluentform/submission_inserted` with `($insertId, $formData, $form)`: local `app/Services/Form/SubmissionHandlerService.php:270`, Matt `:234`. `fluentform/rendering_field_data_select` with `($data, $form)`: `Components/Select.php:31` in both. The same filter runs during submit validation (local `Helpers/Helper.php:1335`, Matt `:1198`), so filled event options validate and draft slugs are rejected. The preselect mechanism (`attributes.value`, overridden by `dynamic_default_value`) is present in Matt's `Select.php:64-68` and `BaseComponent.php:75-99`.
- **FluentBooking hooks:** `after_booking_scheduled` is dispatched as `after_booking_{status}` (local `Services/BookingService.php:84`, Matt `:81`; on confirming a pending booking, `SchedulesController.php:340` / `:324`). `booking_schedule_cancelled` is in `Models/Booking.php:745,758` / `:726,739`. `after_booking_rescheduled` with the booking first is in local `Services/RescheduleService.php:110` and Matt `Hooks/Handlers/FrontEndHandler.php:531`. Booking `start_time` is UTC (Matt `FrontEndHandler.php:527-528`), so the dashboard's UTC to event-zone conversion is right.
- **FluentCRM APIs:** `FluentCrmApi()` (`helpers.php:27` both; `Api/config.php:8-9` maps `contacts` and `tags`). `Contacts::createOrUpdate()` returns `false|Subscriber` (`Contacts.php:123` both). `Tags::importBulk()` returns the models (`Tags.php:29` both). `attachTags`/`detachTags` take arrays of ids (local `Subscriber.php:1315/1476`, Matt `:1266/1438`). `fluentcrm_get/update_subscriber_meta` (local `helpers.php:478/503`, Matt `:445/465`). `SubscriberNote` fillable includes every field used (both). Pivot `object_type` is `FluentCrm\App\Models\Tag` (`Subscriber.php:325-335`), which matches the raw SQL. Every Fluent call is guarded by `sma_crm_ready()` or `defined('FLUENTFORM')` and wrapped in try/catch.
- **Diagnosis rule:** submission `response` is read in only two places, both through allow-lists (`registration.php:102-119` reads the child first name only; `dashboard.php:144-183` reads first name, age, costume/theme and flash). The CRM gets guardian fields only. Emails get first names and event details only. Notes carry slugs and entry ids only. Every `error_log` carries ids, error codes or exception class names, never values. REST responses carry ids, slugs, stages and counts. Public templates show event data only. The CSV has no diagnosis or address column.
- **Escaping:** every echo in `templates/` and `admin/` is escaped with the right function. `sma_dash_badge` builds escaped HTML. The portfolio link goes through `esc_url(..., ['http','https'])`. `mailto:` links go through `esc_url`. Email placeholders are stripped of tags and CR/LF, so there is no header injection.
- **Nonces, caps and redirects:** all three `admin_post_*` handlers check the cap and then `check_admin_referer`. The CSV download is nonce-checked. Every REST route has a `permission_callback`. Redirects use `wp_safe_redirect` + `exit`. The CSV formula guard covers `= + - @ \t \r`. All SQL uses `$wpdb->prepare` with generated `%d`/`%s` lists, and no raw interpolated input.
- **`wp_after_insert_post`** fires after meta and terms on both REST create and REST update (WP 5.6+), and after classic-editor custom fields. Revisions and autosaves are skipped.
- **Capabilities:** administrator and editor get all ten `sma_event` caps. `sma_agent` gets exactly `read`, `edit_sma_events`, `edit_others_sma_events`, `edit_published_sma_events`, `publish_sma_events` and `read_private_sma_events`: no delete and no `edit_posts`, so it can't reach the dashboard, family REST or export. The lazy grant on `init:20` also covers a mounted plugin with no activation, and refreshes the current user's caps.
- **Upcoming boundary:** `>= today` (event-record.php:141-145) and passed `< today` (pages.php:134) are consistent. Events with no date are listed and never marked passed. `date_i18n(fmt, strtotime('Y-m-d'))` formats the right day.
- **Rewrites:** `has_archive` is added through `register_post_type_args` before `init`. The lazy soft flush runs once at `init:99` after registration, and activation marks it stale.
- **Approval order:** the stage is set before the email, and an email failure rolls the family to needs-follow-up. A missing `booking_url` sends nothing and returns 409. Declines are only drafted, never sent (a family's draft in plugin storage, a volunteer's as a contact note).
- **CSS:** every selector is under `.sma` or `sma-`-prefixed, with no bare element or `:root` rules. Templates handle both block and classic themes (`parts/open.php`, `parts/close.php`).
